# 中世日本食事監査 — 経路別小作業マップ

**位置付け**：これは調査作業のルーティング表。原典の史料・既存判定は[食品連鎖・加工品横断監査台帳](FoodProcessingChainAudit.md)、元の98記録は[食品候補整理索引](FoodItemRegister.md)を正本とする。料理や新しいMod機構・数値の採用を意味しない。

## 毎回読む共通条件

1. **全体目的**：古代～戦国末期の日本食文化について「入手原料→一次加工→中間品→完成食品→食べ方／保存／交易」の関係と史料の限界を整理する。表の行数・検証件数を増やすことを目的にしない。
2. **証拠を分ける**：食品の名前、製造工程、実際の供食・流通、普及率／地域／階層、輸入／国内栽培は別々に判定する。近世・現代の工程を中世へ遡及しない。
3. **小作業の単位**：相互に関係する原料・工程・用途を一緒に照合できる経路。**1行・3対象など固定の件数制限は設けない**。大きな群では異なる経路・史料の切れ目で分ける。
4. **既存成果を継ぐ**：原台帳のC年代照合に既に存在する結果と留保を先に紐付け、同じ調査を繰り返さない。別群と重なる原料・加工・料理は相互参照し、削除や確定統合を先取りしない。
5. **境界と停止**：B候補の整理・既存Cとの照合・限定的D矛盾点検が現在の仕事。**全体D網羅は未達**。E既存Mod比較、F実装採否は別工程。後続の選定は[現行選定ルール](FoodCultureGameplayDesignConstraints.md)の「食文化→現行システムの価値評価→OH要否→採否・実装方法」に従う。歴史重要度による絞り込み結果は[別文書](FoodHistoricalSelection.md)へ記録する。文化的保持対象は同性能でも残し、保存加工の利点を料理OHの価値と混同しない。選定ルールの設定だけでは進捗を変更しない。2026-10-28の実作業による部分接続は下記進捗欄に記録した。
6. **終了条件**：当該経路の原料・工程・用途の対応、既存出典の支持範囲、別群の参照先、史料不足／時代外／未処理部分、次の開始点が明示できたら終了。新規の実質的な事実・矛盾だけ原台帳へ記録する。

## 調査対象の母集団と、照合漏れ防止

本マップは**旧96候補行と新98棚卸し行を接続する入口**である。**96+98は食品の数でも、全調査対象の合計でもない**。同じ原料・料理・加工・用途が複数の原表に現れる。以下のすべてを照合対象とし、今回の小作業に関係する箇所だけ読む。

## 全群に共通する横断点検

- **穀類と菓子**：WG01→WG02/WG03。糒（調理した飯を干す）、焼米（籾を炒る）、油炒り米、製粉は同じ製法ではない。
- **豆と調味**：WG04↔WG14。豆腐／湯葉／納豆と味噌／醤油・麹の中間品・製造工程は分け、豆原料の重複を二重計上しない。
- **野菜・山野・果実と加工保存**：WG05–WG08↔WG15。干す／漬けるは用途・工程であり、すべてを独立食品数には数えない。
- **魚介・海藻と調味・保存**：WG09–WG12↔WG14/WG15。身・内臓・魚醤・煮出し汁・干物を別経路とし、江戸以降の製法名と混同しない。
- **精進料理と食肉**：WG07/WG13↔WG15。鴨・猪・雁などの料理名から実肉の使用を推定しない。
- **食事文化・Mod設計**：日常・儀礼・贈答・軍糧・上層の供応を用途・社会的位置付けとして保持。史料のある料理をそのまま追加Recipe案に変換しない。

## 経路を閉じる前の横断整合ゲート（**毎回**）

1. 同じ原料・加工・完成品・料理・用途が他のWG、旧96候補ID、B98元行、初期34経路にないか、**その経路に関連するものだけ**照合する。工程の異なる乾飯／焼米や魚の身／内臓等は安易に統合しない。
2. 既存Cの史料が支持するのは名称／製法／供食／地域・階層・普及のどれか。後世製法を遡及していないか。出典未確認を「存在しない」とも「全件未検証」ともしない。
3. WG内で誤りを見つけたら、他群の関係にも影響するかを確認し、必要箇所の矛盾を処理する。**WG15の最終検査まで矛盾を放置しない。** 両立不能・史料不足なら未解決として引き継ぎ、勝手に事実を確定しない。
4. この経路で新たな追加史料を探す必要があるか。既存の根拠で接続と限界を表現できるなら再調査しない。**史料探索に終わりがなくなる場合、具体的な不足を書いて停止する**。E/Fの実装判断を先取りしない。

WG15はこの**毎回の横断照合に加え**、全群の整理が進んだ後の未検査領域の総覧を担当する。最後だけに初めて横断チェックする工程ではない。
